## 2. 当前结论

当前项目已经完成一套可运行的具身智能仿真数据 Mini-Pilot：

- 使用 MJWarp/MuJoCo 作为唯一物理真源；
- 使用 Unity 6 URP 进行机器人可视化和多模态图像采集；
- 正式接入 Franka Emika Panda 七自由度单臂和平行夹爪；
- 已实现抓取放置和定位销插入两个 Panda 任务；
- 能生成状态、动作、图像、深度、分割、接触、任务指标和随机化元数据；
- 能导出原生 HDF5、LeRobot v3 和 robomimic 三种数据格式；
- 能生成数据卡、字段说明、质量报告、许可证清单、SHA256 清单、读取示例和独立校验程序；
- 已跑通状态行为克隆训练、离线评估和闭环评估。

但当前仍属于“厂商接口评审样例”，不是成熟训练数据产品：

- 正式交付批次只有 10 个 Panda Episode、3,883 个 transition；
- 正式批次全部是专家成功轨迹，缺少足量恢复轨迹和结构化失败轨迹；
- 行为克隆模型离线误差较低，但在未见 seed 上闭环成功率为 0%；
- 尚未连接真实 Panda、厂商控制器、ROS 2 或真实相机；
- 尚未完成 Sim-to-Real 验证，不能承诺真实机器人成功率。

因此，当前最准确的项目定位是：

> 已经具备“生成标准化 Panda 仿真数据并交给厂商做读取、字段、质量和训练接口评审”的能力；尚不具备“直接交付可在真实机器人上稳定工作的策略或大规模训练数据集”的能力。

```text

    ↓
```

各组件职责：

| 组件 | 当前职责 |
|---|---|
| MJWarp / MuJoCo 3.11.0 | 关节、刚体、接触、约束、奖励、成功判定和策略执行；是唯一物理真源 |
| Unity 6000.3.11f1 + URP 17.3.0 | 场景显示、Panda mesh 绑定、灯光与相机随机化、多模态视觉采集、操作面板 |

| HDF5 Schema 2.0 | 保存完整且无时序歧义的 Episode 数据 |
| LeRobot v3 / robomimic | 面向厂商现有机器学习工具的兼容交付格式 |

### 4.2 任务与策略

当前工程包含 6 个场景，其中前 4 个是早期抽象任务，后 2 个是当前正式 Panda Pilot 任务。

| 场景 ID | 设备抽象 | 任务 | 当前定位 |
|---|---|---|---|
| `planar_push` | 二维双关节机械臂 | 推动物体到目标区 | 早期数据链路验证 |
| `precision_insert` | 二维双关节机械臂 | 方块导向插入 | 早期接触任务验证 |
| `quality_inspection` | 二维双关节机械臂 | 多工位到位 | 早期状态控制验证 |
| `warehouse_navigation` | 二维移动底盘 | 仓储导航与避障 | 早期移动任务验证 |
| `panda_pick_place` | Franka Panda | 抓取方块并放入目标料盒 | 当前正式 Pilot 任务 |
| `panda_peg_insert` | Franka Panda | 抓取定位销并插入孔位 | 当前正式 Pilot 任务 |

已实现的数据生成策略：

| 策略 | 逻辑 | 当前用途 |
|---|---|---|
| `expert` | 状态机、逆运动学和关节位置控制生成标准成功路径 | 生成名义专家数据 |
| `recovery` | 在指定阶段注入短时扰动，再恢复专家控制 | 生成“偏离后修正”的成功数据 |
| `perturbed` | 连续关节命令噪声，并按 seed 注入受控失败 | 生成失败、卡死、越界等负样本 |
| `random` | 随机动作 | 建立随机策略下限和风险样本 |
| `learned` | 加载训练后的行为克隆模型闭环推理 | 评估数据能否支持学习控制 |

需要注意：最终 `PandaMiniPilotV02Final` 交付包当前只包含 `expert` 成功轨迹；`recovery` 和 `perturbed` 已做小规模物理验证，但尚未进入正式交付数据集。

`recovery` 已在 Python 任务策略和 Mini-Pilot 命令行中实现，但 Unity 当前默认批量采集计划仍以 `expert + perturbed` 为主。v0.3 正式采集前，需要把 `recovery` 加入 Unity 批量计划和界面选择，并把扰动窗口写入逐帧数据。

### 4.4 数据记录与 Schema 2.0

Schema 2.0 明确使用：

```text
observation_t
    ↓
action_t
    ↓
reward_t / done_t
    ↓
next_observation_t
```

每个 Episode 保存 `N+1` 个 observation 和 `N` 个 transition：

```text
transition_observation_index[t]      = t
transition_next_observation_index[t] = t + 1
```

这解决了早期 Schema 中“动作和动作后状态写在同一行”可能造成的一帧偏移问题。

记录器还会检查：

- 状态 frame ID 与 Unity 图像 frame ID 必须一致；
- frame ID 必须连续；
- 初始帧标识必须正确；
- Episode 关闭时 observation 数量必须等于 transition 数量加 1；
- 写入时先保存为 `.partial`，完整关闭后再原子重命名为 `.h5`。

## 5. 当前适配的机器人和设备

### 5.1 正式适配：Franka Emika Panda

当前真正按照标准机器人结构接入的是：

```text
Franka Emika Panda 七自由度机械臂 + 两指平行夹爪
```

关键参数：

| 项目 | 当前实现 |
|---|---|
| 机械臂自由度 | 7 |
| 夹爪 | 两个手指关节，对外合并为 1 维宽度命令 |
| 实际动作维度 | 8：7 个关节位置目标 + 1 个夹爪宽度 |
| 机械臂动作单位 | rad |
| 夹爪动作单位 | m |
| 末端 body/site | `hand` / `gripper` |
| 控制方式 | `joint_position_target` |
| 控制频率 | 20 Hz |
| 物理与 mesh 来源 | MuJoCo Menagerie Franka Panda |
| 上游版本 | `da76818e269b82289eba39808e2fb91d679d6994` |
| 上游许可证 | Apache-2.0 |

受控关节包括：

```text
joint1, joint2, joint3, joint4, joint5, joint6, joint7,
finger_joint1, finger_joint2
```

对外执行命令为：

```text
joint_position_target[7] + gripper_width[1]
```

`observations/qpos` 是整个 MuJoCo 场景状态，当前正式文件中维度为 16，可能同时包含机器人、夹爪和物体自由关节；厂商如果只需要机器人状态，应优先读取 `observations/joint_position` 和机器人定义元数据，不应默认把全部 `qpos` 都解释为机械臂关节。

## 6. Panda 数据的生成逻辑

### 6.1 Episode 生成流程

每条数据大致经过以下步骤：

1. 选择任务、策略和 seed；
2. MJWarp 加载 Panda MJCF、任务物体、目标区域和相机配置；
3. 根据 seed 生成物体位置、目标位置、物理参数和视觉随机化参数；
4. 专家状态机计算当前任务阶段；
5. 逆运动学生成关节目标；
6. 控制器执行 7 维关节位置目标和 1 维夹爪宽度命令；
7. MJWarp 推进物理并计算状态、接触、奖励和成功条件；
8. Unity 同步所有 body/link 姿态并采集同 frame ID 图像；
9. Recorder 写入 `observation_t -> action_t -> observation_t+1`；
10. Episode 成功、失败或超时后写入结构化终止原因；
11. validator 检查文件；
12. 通过的数据进入 manifest、数据划分、质量报告和格式导出。

### 6.2 随机化

当前已记录的随机化信息包括 seed、随机化组、物体配置 ID、场景配置 ID，以及实际使用的物体、场景和视觉参数。已有实现覆盖：

- 物体初始位置；
- 目标位置或孔位；
- 物体尺寸；
- 质量和摩擦；
- 颜色和灯光；
- 固定相机的小范围位置随机化；
- 任务相关初始条件。

相同 seed 用于保证初始状态和随机化结果可复现。

### 6.3 失败和恢复数据

小规模验证结果：

| 策略 | 抓放 | 插入 | 结论 |
|---|---:|---:|---|
| `perturbed` | 1/5 成功 | 0/5 成功 | 适合作为失败数据来源 |
| `recovery` | 5/5 成功 | 5/5 成功 | 适合作为成功恢复数据来源 |

目前已有终止原因包括：

- `success`；
- `object_out_of_bounds`；
- `grasp_failed_or_timeout`；
- `insertion_jam_or_timeout`；
- `timeout`。

这些分类仍然偏粗。下一阶段需要把“未抓住、滑落、偏轴、卡死、碰撞过大、放置越界、超时”等原因拆成互斥且可统计的标签。

| 字段 | 含义 |
|---|---|
| `actions/command` | 实际执行命令：7 维关节位置目标 + 1 维夹爪宽度 |

接触信息包括：

- 接触数量；
- 有效标记；
- geom pair；
- body pair；
- category pair；
- 接触类型和是否目标接触；
- 接触位置；
- 接触法向；
- 接触距离/穿透；

- 轴向偏差；
- 最大目标穿透；

其中 `object_contact_load_n` 当前实测恒为 0，不能作为有效的力控监督标签。该字段必须修复后才能向厂商声明可用于力控训练。

## 8. 能够提供的数据格式

### 8.1 原生 Schema 2.0 HDF5

定位：内部信息最完整的数据真源，也是追溯和质量审计格式。

优点：

- 保存深度、实例 ID、接触、任务指标和完整随机化元数据；
- 明确保存 N+1 observation 与 N transition；
- 便于逐 Episode 校验、追溯和重新导出；
- 适合厂商自定义 DataLoader。

限制：

- 不是所有训练框架的默认格式；
- 图像直接保存在 HDF5 中，文件较大。

### 8.2 LeRobotDataset v3

定位：当前首要外部机器学习交付格式。

当前目录结构包含：

- 每 Episode 一个 Parquet 状态/动作文件；
- 前视相机 MP4；
- 腕部相机 MP4；
- `info.json`、`stats.json`、`tasks.jsonl`；
- Episode 元数据 Parquet。

优点是便于接入 Hugging Face LeRobot 生态和常见模仿学习流程。部分原生 HDF5 中的高密度接触、深度和完整随机化信息不会完全等价地进入 LeRobot 格式，因此 HDF5 仍需保留。

### 8.3 robomimic HDF5

定位：兼容 robomimic 的模仿学习数据读取和训练习惯。

当前交付为：

```text
robomimic/dataset.hdf5
```

内部包含 10 个 demo，并带 train/validation/test 掩码或分组信息。

### 8.4 暂未提供的格式

当前未正式实现或未纳入 P0：

- ROS 2 MCAP；
- RLDS / TFDS；
- 某个厂商私有格式；
- 真实机器人日志；
- VLA 大模型专用语言指令和文本标注格式。

## 9. 当前训练方式

### 9.1 数据生成不是强化学习

当前专家数据使用脚本状态机、逆运动学和关节控制器生成。这样可以先获得可解释、可复现的标准轨迹，不把强化学习训练是否成功作为数据生产的前置条件。

### 9.2 已正式验证：状态行为克隆

当前行为克隆模型：

- 框架：PyTorch；
- 网络：三层 MLP，隐藏层为 `256 × 256 × 256`；
- 输出层：`Tanh`；
- 输入字段：`qpos + qvel + goal_position + task_stage`；
- Panda 输入维度：35；
- Panda 输出维度：8；
- 输出：归一化关节位置目标和夹爪命令；
- 归一化参数只由训练集计算；
- 抓放和插入分别训练，不混合任务。

数据按照 Episode 和共享身份分组为 train/validation/test，避免同一 seed、物体配置、场景配置或随机化组跨集合泄漏，不按帧随机切分。

评估分为两层：

1. 离线评估：计算动作 MAE、MSE、方向一致性和各任务阶段误差；
2. 闭环评估：在未见 seed 上分别运行专家、随机和学习策略。

### 9.3 已实现代码但未作为本轮正式验收的训练案例

工程还实现了：

| 训练类型 | 模型 | 用途 | 当前状态 |
|---|---|---|---|
| 动力学模型 | MLP | 预测下一状态和奖励 | 代码与数据加载链路已实现 |
| 风险预测 | GRU | 预测成功、严重碰撞、越界、超时等风险 | 代码已实现，需更多失败数据 |
| 实例分割 | 轻量视觉网络 | 从实例 ID 监督训练视觉分割 | 代码已实现，非本轮 Panda 正式验收项 |

这些能力说明数据能被用于多类训练，但当前正式 Panda v0.2 结论仍应以行为克隆实测为准。

### 9.4 行为克隆实测结果

| 任务 | 最佳 validation MSE | test MAE | test MSE |
|---|---:|---:|---:|
| 抓取放置 | 0.000084 | 0.007500 | 0.000402 |
| 定位销插入 | 0.000505 | 0.005442 | 0.000151 |

未见 seed 10000～10009 的闭环结果：

| 任务 | 专家 | 随机 | 学习策略 |
|---|---:|---:|---:|
| 抓取放置 | 100% | 0% | 0% |
| 定位销插入 | 100% | 0% | 0% |

离线误差低但闭环失败，说明模型只学会了训练轨迹附近的动作。一旦产生小误差并进入训练数据没有覆盖的状态，误差会继续累积。根因主要是每个任务只有 3 条训练 Episode，且几乎都是单一路径的成功专家轨迹。

## 12. 已知问题和风险

### 12.1 数据规模与分布不足

正式数据只有每个任务 5 个 seed，训练集中每任务实际只有 3 条 Episode。数据几乎都是名义成功路径，模型没有见过足够多的偏离、恢复和失败状态。

### 12.2 接触载荷字段无效

`object_contact_load_n` 当前来自 MJWarp `cfrc_ext`，实测恒为 0。需要研究 `efc_force` 或 contact constraint force，并用可控载荷测试校准。

### 12.3 插入任务使用已披露的 expert weld

插入任务在抓取后运输阶段使用 expert weld 稳定定位销，并在物理插入前释放。该做法降低了运输阶段难度，必须在数据卡中持续披露，后续应评估去除 weld 后的真实抓持稳定性。

### 12.4 动作表示可能不利于恢复

当前执行动作是绝对关节位置目标。绝对目标容易拟合名义轨迹，但不一定适合从分布外状态恢复。后续需要与以下表示对比：

- delta joint position；
- delta end-effector pose + gripper；
- 厂商控制器实际支持的 action space。

### 12.5 失败类型仍不够细

`grasp_failed_or_timeout` 和 `insertion_jam_or_timeout` 把多个原因合并在一起，不利于风险模型训练、数据筛选和厂商定位问题。

### 12.6 缺少真实机器人和厂商验收

尚无真实 Panda、真实相机、真实标定和厂商控制栈测试。坐标、动作、频率和字段虽然有定义，但还没有被外部团队独立验收。

### 12.7 项目级数据许可仍需补齐

当前已保留 Panda 第三方资产 Apache-2.0 许可证，但仓库根目录尚未发现项目代码许可证或自生成数据的明确交付许可条款。对外商业交付前需要补充：

- 项目代码 LICENSE；
- 自生成数据 DATA_LICENSE 或数据使用协议；
- 是否允许厂商内部训练、再分发、衍生模型和商业使用；
- 第三方资产与生成数据之间的许可边界说明。

## 13. 下一阶段建议：Panda Pilot v0.3

下一阶段不建议立即生产 1,000 条相似轨迹。应先用 100 条有结构的数据证明学习策略能从 0% 提升到可用水平。

### 13.1 P0：先修数据合同和关键真实性问题

必须先完成：

1. 将扰动幅度、窗口、恢复起止帧写入 Episode 元数据和逐帧字段；
2. 拆分失败类型，形成互斥的枚举和判定规则；
3. 修复 `object_contact_load_n`，增加接触力方向、大小和来源说明；
4. 增加可控接触载荷单元测试；
5. 明确项目代码和生成数据的商业许可；
6. 冻结 v0.3 Schema，不在生产过程中随意改字段。

建议新增字段：

- `disturbance_profile`；
- `disturbance_window_start/end`；
- `disturbance_std`；
- `disturbance_active`；
- `failure_type`；
- `recovery_started_frame`；
- `recovered_to_nominal_frame`；
- `recovery_duration_frames`；
- `pre_disturbance_state_error`；
- `maximum_post_disturbance_state_error`。

### 13.2 P1：生产 100 条结构化 Episode

每个任务生产 50 条：

| 数据类型 | 每任务数量 | 预期结果 | 用途 |
|---|---:|---|---|
| nominal expert | 20 | 成功 | 学习标准路径 |
| recovery | 20 | 成功 | 学习偏离后的修正 |
| perturbed failure | 10 | 失败 | 训练风险模型和定义数据边界 |

生产顺序：

1. 对候选 seed 先运行无图 physics preflight；
2. 过滤明显损坏、穿透过大或任务逻辑错误的轨迹；
3. 将 Unity 批量计划改为 nominal、recovery、failure 三类明确配额；
4. 再进入 Unity 采集前视和腕部视觉；
5. 每条 Episode 立即运行 Native validator；
6. 全批次完成后再做 split、导出、质量报告和 SHA256。

### 13.3 P2：改进训练采样和闭环评估

训练建议：

- 行为克隆只使用 nominal expert 和 recovery 成功轨迹；
- perturbed failure 先用于风险分类，不直接作为动作监督；
- 对扰动窗口和恢复窗口提高采样权重；
- 抓放和插入分别训练；
- 固定 seed 10000 起的评估集，禁止进入数据生产；
- 同时报告离线误差和闭环成功率，不能只看 MSE。

v0.3 建议验收门槛：

| 指标 | 抓放 | 插入 |
|---|---:|---:|
| 专家未见 seed 成功率 | ≥90% | ≥75% |
| recovery 数据成功率 | ≥80% | ≥80% |
| 学习策略闭环成功率 | ≥50% | ≥30% |
| 相对随机策略提升 | ≥30 个百分点 | ≥30 个百分点 |

通用质量门槛继续保持：

- 文件读取成功率 100%；
- 状态/动作/图像错帧为 0；
- NaN、Inf、反向时间戳和损坏 Episode 为 0；
- checksum 通过率 100%；
- split 无 seed、对象、场景和随机化组泄漏；
- 插入目标穿透小于既定门槛；
- 相机关键阶段目标可见率达到门槛。

### 13.4 P3：若闭环仍失败，做动作表示对比

如果 recovery 数据加入后仍未达到门槛，不应直接扩大网络或盲目增加相似数据。应在同一批数据和同一评估 seed 上比较：

1. absolute joint position；
2. delta joint position；
3. delta end-effector pose + gripper。

需要同时比较：

- 闭环成功率；
- 恢复时间；
- 动作平滑性；
- 关节限位和安全层阻断比例；
- 对随机化和初始偏差的鲁棒性；
- 与真实厂商控制接口的匹配程度。

### 13.5 P4：找一家厂商做正式接口验收

在扩展到 400 或 1,000 条前，应先邀请一家目标厂商完成：

1. 独立运行 `validate_delivery.py`；
2. 使用自己的 Python 环境读取三种格式；
3. 确认机器人关节顺序、坐标系、单位和 action space；
4. 使用厂商 DataLoader 读取样例；
5. 复现至少一个训练基线；
6. 提出缺失字段和格式修改意见；
7. 确认真实机器人控制器需要 absolute、delta joint 还是 delta Cartesian action；
8. 确认真实相机、力传感器、控制频率和时间同步要求。

只有厂商完成读取和字段验收后，才能准确决定后续是否需要 ROS 2 MCAP、私有格式或其他相机/力控字段。

### 13.6 P5：通过门槛后再扩大数据规模

建议扩展顺序：

```text
10 条接口样例（已完成）
    ↓
100 条结构化训练验证集（下一目标）
    ↓ 闭环达到 50% / 30%
每任务 200 条，共 400 条
    ↓ 闭环挑战 70% / 50%
厂商真实 Panda 小规模验证
    ↓
根据真实失败分布定向补数据
    ↓
再评估是否生产 1,000 条或更大规模
```

## 16. 最终判断

当前项目最有价值的成果不是已经训练出了可部署机器人策略，而是已经把以下链路完整跑通：

```text
真实机器人结构建模
→ 标准任务设计
→ 可复现仿真轨迹生成
→ 同步多模态数据记录
→ 无歧义数据合同
→ 标准格式导出
→ 数据质量验证
→ 模仿学习训练
→ 未见场景闭环评估
→ 明确暴露数据不足和技术风险
```

下一阶段的核心不应是“生成更多同样的成功轨迹”，而应是“生成能够教会模型恢复的结构化数据，并通过厂商和未见 seed 闭环验收”。只有完成这一步，项目才会从数据接口 Demo 进入真正的数据产品和机器人训练系统阶段。
